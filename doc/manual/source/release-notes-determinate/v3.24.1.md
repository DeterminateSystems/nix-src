# Release 3.24.1 (2026-10-25)

* Based on [upstream Nix 2.35.3](../release-notes/rl-2.35.md).

## Garbage collection performance regression fix

Since Determinate Nix 3.23.0, large evaluations could spend most of their time in garbage collection: once the heap grew beyond 4 GiB, a full collection was triggered after every 16 MiB of allocation. In one of our CI jobs, this made evaluation go from about 2 minutes to about 40 minutes. The garbage collector once again allows the heap to grow several times between collections, as it did before 3.23.0.

In our [flake regression tests](https://github.com/DeterminateSystems/flake-regressions) (249 flakes, single-threaded evaluation), the total CPU time dropped from 7014 to 806 seconds. The effect is concentrated in flakes that need a large heap, at the cost of a somewhat higher peak memory usage:

| Flake                      | Elapsed time | CPU time     | Peak memory        |
| -------------------------- | ------------ | ------------ | ------------------ |
| `Mic92/sops-nix/8b89f44`   | 283s → 52s   | 3097s → 66s  | 9.8 GiB → 11.0 GiB |
| `NixOS/nix/2.21.2`         | 292s → 94s   | 2582s → 119s | 9.5 GiB → 10.7 GiB |
| `zhaofengli/attic/0.1.165` | 37s → 33s    | 90s → 35s    | 4.7 GiB → 5.4 GiB  |

PR: [DeterminateSystems/nix-src#725](https://github.com/DeterminateSystems/nix-src/pull/725)
