# Release 3.24.3 (2026-11-18)

* Based on [upstream Nix 2.35.6](../release-notes/rl-2.35.md).

## Faster garbage collection

The garbage collector no longer traverses the closure of every GC root from scratch. Previously, when many roots shared most of their closures (as is common with system generations and profiles), it traversed the shared paths again for every root. It now stops at paths that it already knows to be alive. For example, `nix-store --gc --print-dead` on a store with 143,310 live and 34,327 dead paths went from 39.7s to 16.2s.

In addition, other Nix processes no longer stall while a garbage collection is running. Evaluations, builds and `nix copy` register temporary roots with the garbage collector, and these registrations could block for as long as the collector took to compute the closure of a temporary root, e.g. more than a second for a closure of 20,000 paths.

PRs: [DeterminateSystems/nix-src#769](https://github.com/DeterminateSystems/nix-src/pull/769) by @czawistowski-nvidia, [DeterminateSystems/nix-src#805](https://github.com/DeterminateSystems/nix-src/pull/805)

## Garbage collector progress

`nix store gc` now shows its progress in the progress bar, instead of giving no feedback until it finishes:

```console
[301 paths alive, 355 paths deleted, 1.4 MiB freed] deleting garbage
```

With `--dry-run`, it shows the number of live and dead paths found so far. This also works when the garbage collection is performed by the Nix daemon. The stages of a garbage collection (such as finding roots and deleting garbage) also show up as OpenTelemetry spans.

PR: [DeterminateSystems/nix-src#808](https://github.com/DeterminateSystems/nix-src/pull/808)

## Faster evaluation

Several changes make evaluation faster, in particular of NixOS configurations. Unless noted otherwise, these timings are for single-threaded evaluation.

* Nix no longer uses exceptions internally to check whether a path is a store path, which happened tens of thousands of times when evaluating a NixOS system. This reduced the evaluation time of a NixOS system from 5.49s to 5.21s.
* In pure evaluation mode (e.g. when evaluating flakes), checking whether the evaluator may access a file is much cheaper. This reduced the evaluation time of a NixOS system from 5.15s to 4.94s.
* Serialising derivations that use structured attributes (such as those produced by `fetchurl` in Nixpkgs) no longer makes a copy of all their attributes, which saves about 1% of the instructions of a NixOS system evaluation.
* Errors that propagate through many thunks are handled more cheaply. This reduced the CPU time of `nix-env -qa --drv-path -A haskellPackages` by 1.2%.
* With multi-threaded evaluation, each thread now preallocates less memory from the garbage collector at a time. With 24 evaluation threads, this reduced the peak memory usage of `nix eval --json nixpkgs#firefox` by 28% and its run time by 11%.

PRs: [DeterminateSystems/nix-src#762](https://github.com/DeterminateSystems/nix-src/pull/762), [DeterminateSystems/nix-src#763](https://github.com/DeterminateSystems/nix-src/pull/763), [DeterminateSystems/nix-src#770](https://github.com/DeterminateSystems/nix-src/pull/770), [DeterminateSystems/nix-src#780](https://github.com/DeterminateSystems/nix-src/pull/780), [DeterminateSystems/nix-src#800](https://github.com/DeterminateSystems/nix-src/pull/800)

## Fewer stack overflows in the evaluator

Nix could crash with a stack overflow on long chains of attribute selections, such as those created by overlays that do `x = prev.x`, because the [`max-call-depth`](../command-ref/conf-file.md#conf-max-call-depth) setting only limited the depth of function calls. Attribute selections now count towards `max-call-depth`, so such evaluations fail with a `stack overflow; max-call-depth exceeded` error and a stack trace instead. Normal evaluations stay well below the default limit of 10,000: a NixOS system evaluation needs a depth of 200 to 300.

PR: [DeterminateSystems/nix-src#775](https://github.com/DeterminateSystems/nix-src/pull/775)

## Bug fixes

* After `nix flake update` updates a FlakeHub input such as `https://flakehub.com/f/NixOS/nixpkgs/0.2605`, the next command no longer downloads the input again. More generally, tarballs whose URL contains a `+` are now found in the tarball cache. PR: [DeterminateSystems/nix-src#760](https://github.com/DeterminateSystems/nix-src/pull/760)
* Downloads from binary caches that don't support HTTP/2 multiplexing (such as S3 or plain `http://` caches) no longer fail with `Timeout was reached` or print spurious "retrying" warnings when all [`http-connections`](../command-ref/conf-file.md#conf-http-connections) are busy. Time spent waiting for a free connection no longer counts towards [`connect-timeout`](../command-ref/conf-file.md#conf-connect-timeout). PR: [DeterminateSystems/nix-src#789](https://github.com/DeterminateSystems/nix-src/pull/789)
* Fix the garbage collector deleting a path that has a GC root, if the process doing the garbage collection (e.g. a Nix daemon worker or a process doing an automatic garbage collection) had looked up the path before it became valid. PR: [DeterminateSystems/nix-src#806](https://github.com/DeterminateSystems/nix-src/pull/806)
* `nix-store --gc --print-dead`, `nix-store --gc --print-live` and `nix store gc --dry-run` no longer delete entries in the Nix store that aren't store paths, such as stale temporary directories. PR: [DeterminateSystems/nix-src#809](https://github.com/DeterminateSystems/nix-src/pull/809), cherry-picked from [NixOS/nix#16578](https://github.com/NixOS/nix/pull/16578) by @iamanaws
* On macOS, garbage collection no longer fails with `Operation not permitted` on app bundles in the Nix store whose permissions are protected by App Management. PR: [DeterminateSystems/nix-src#807](https://github.com/DeterminateSystems/nix-src/pull/807), cherry-picked from [NixOS/nix#16626](https://github.com/NixOS/nix/pull/16626) by @booxter
* `ssh-ng://` stores no longer leave an SSH master process and a temporary directory behind after Nix exits. PRs: [DeterminateSystems/nix-src#781](https://github.com/DeterminateSystems/nix-src/pull/781), [DeterminateSystems/nix-src#786](https://github.com/DeterminateSystems/nix-src/pull/786), [DeterminateSystems/nix-src#787](https://github.com/DeterminateSystems/nix-src/pull/787)
* Fix a crash (`pure virtual method called`) when Nix exits while a download from a substituter is still in progress, e.g. in `nix flake check`. This was a regression in 3.23.3. PR: [DeterminateSystems/nix-src#794](https://github.com/DeterminateSystems/nix-src/pull/794)
* Fix rare crashes in `nix build` and `nix-daemon` when Nix is interrupted, e.g. with Ctrl-C or when a client disconnects from the daemon. PR: [DeterminateSystems/nix-src#795](https://github.com/DeterminateSystems/nix-src/pull/795)
* Closure queries through the Nix daemon or an `ssh-ng://` store (e.g. `nix path-info --recursive` or `nix copy --from`) no longer hang when the store's `max-connections` setting is smaller than the depth of the closure. PR: [DeterminateSystems/nix-src#777](https://github.com/DeterminateSystems/nix-src/pull/777) by @jwiegley
* With multi-threaded evaluation, `builtins.fetchTree` and flake inputs no longer get the `lastModifiedDate` of another input that is fetched at the same time. PR: [DeterminateSystems/nix-src#793](https://github.com/DeterminateSystems/nix-src/pull/793) by @jmoo
* `nix copy --to` a binary cache now fails if the contents of a store path don't match its recorded NAR hash or size (e.g. because the path was modified after it was registered), rather than uploading a `.narinfo` that makes substitution of the path fail for every client. The same applies to `nix nario import` into a binary cache. PR: [DeterminateSystems/nix-src#766](https://github.com/DeterminateSystems/nix-src/pull/766) by @czawistowski-nvidia
* Fix a crash (`stack pointer ... is not within the stack ... that is being switched away from`) in deep evaluations that copy sources to the store. This mostly affected the statically linked build of Nix; other builds were only affected by evaluations that use more than 8 MiB of stack. PR: [DeterminateSystems/nix-src#784](https://github.com/DeterminateSystems/nix-src/pull/784)
* Fix the Nix daemon aborting with an assertion failure when the garbage collector deletes a derivation that is about to be built, e.g. with `nix build /nix/store/...drv^*`. PR: [DeterminateSystems/nix-src#791](https://github.com/DeterminateSystems/nix-src/pull/791)
* `nix store verify` no longer aborts with an assertion failure on a text-hashed store path whose metadata claims that it refers to itself (e.g. because of a corrupt Nix database). It now reports the path as failed and continues with the other paths. PR: [DeterminateSystems/nix-src#799](https://github.com/DeterminateSystems/nix-src/pull/799)
* `builtins.getFlake` no longer aborts with an assertion failure on a `path:` flake reference to a store path with a `dir` attribute that contains a slash, e.g. `path:/nix/store/...?dir=a/b`. This was a regression in 3.22.0. PR: [DeterminateSystems/nix-src#758](https://github.com/DeterminateSystems/nix-src/pull/758)
* `nix fmt` now prints an error instead of aborting if the flake doesn't have a local source directory. PR: [DeterminateSystems/nix-src#761](https://github.com/DeterminateSystems/nix-src/pull/761)
* The Mercurial fetcher no longer aborts on a branch whose name contains a space, and prints an error if a revision doesn't match exactly one revision. PR: [DeterminateSystems/nix-src#778](https://github.com/DeterminateSystems/nix-src/pull/778)
* Exceeding a file size limit (e.g. set using `ulimit -f` or systemd's `LimitFSIZE=`) now causes a `File too large` error instead of killing Nix. PR: [DeterminateSystems/nix-src#774](https://github.com/DeterminateSystems/nix-src/pull/774)
* The terminal cursor is no longer left invisible when Nix crashes while showing the progress bar. PR: [DeterminateSystems/nix-src#783](https://github.com/DeterminateSystems/nix-src/pull/783)
* `nix serve --port-file` now writes the port file atomically, so a process waiting for the file can no longer read it while it's still empty. PR: [DeterminateSystems/nix-src#771](https://github.com/DeterminateSystems/nix-src/pull/771)

## Fixes from upstream Nix 2.35.6

* On macOS, sandboxed builds with many inputs (up to about 10,000 store paths) no longer fail because the sandbox profile is too large.
* `nix profile upgrade` no longer upgrades packages from Git flakes that haven't changed.
* `builtins.toXML` on a path in a flake, and `nix run` on an app whose `program` is a path in a flake, use the path in the Nix store rather than the path in the flake's source directory. Previously, `nix run` failed with `app program '...' is not in the Nix store`.
* `builtins.readDir builtins.storeDir` works again.
* `nix-shell` no longer crashes on a derivation with structured attributes that contain a `%` character.
* Truncated Brotli-compressed data now causes an error instead of making Nix hang.
* Nix no longer requires read permission on the root directory (`/`), which some sandboxes and nix-on-droid don't provide.
* Nix sends fewer progress updates during downloads and `nix copy`, which reduces the overhead of the progress bar.

PR: [DeterminateSystems/nix-src#792](https://github.com/DeterminateSystems/nix-src/pull/792)

## Performance improvements

* When [`fsync-store-paths`](../command-ref/conf-file.md#conf-fsync-store-paths) is enabled, Nix now starts writing large files to disk while it is still receiving them from a substituter, rather than writing the whole file when it's complete. This reduced the time to substitute a closure with several large files by 14%. PR: [DeterminateSystems/nix-src#765](https://github.com/DeterminateSystems/nix-src/pull/765) by @czawistowski-nvidia

## Miscellaneous changes

* Per-evaluator state of builtins such as `builtins.match` and `builtins.wasm` is now kept in extensions of the evaluator state. As a result, `:reload` in the REPL now clears the `builtins.wasm` module cache. PR: [DeterminateSystems/nix-src#788](https://github.com/DeterminateSystems/nix-src/pull/788)
* An integer overflow when computing the size of an evaluator allocation now makes Nix exit with the out-of-memory status, like other out-of-memory conditions. PR: [DeterminateSystems/nix-src#779](https://github.com/DeterminateSystems/nix-src/pull/779)
* Fix work items in an internal thread pool not starting until the pool is explicitly drained. This doesn't affect current uses of the thread pool. PR: [DeterminateSystems/nix-src#718](https://github.com/DeterminateSystems/nix-src/pull/718) by @czawistowski-nvidia
* Update Nixpkgs. PR: [DeterminateSystems/nix-src#804](https://github.com/DeterminateSystems/nix-src/pull/804)
* CI: Check formatting again. PR: [DeterminateSystems/nix-src#759](https://github.com/DeterminateSystems/nix-src/pull/759)
* CI: Use the Nix that was just built. PR: [DeterminateSystems/nix-src#796](https://github.com/DeterminateSystems/nix-src/pull/796)
* The OpenTelemetry functional test is no longer skipped by the `nix-make` test runner. PR: [DeterminateSystems/nix-src#790](https://github.com/DeterminateSystems/nix-src/pull/790)
